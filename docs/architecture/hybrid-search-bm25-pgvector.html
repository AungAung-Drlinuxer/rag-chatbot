Hybrid Search Engine Architecture — pgvector + BM25 + RRF

Detailed technical topology: Parallel Semantic Vector Search (HNSW) & Two-Tier Lexical BM25 Search with Reciprocal Rank Fusion & Cross-Encoder Reranking

Branch A: Dense Vector (pgvector)

  • • Model: Local Ollama nomic-embed-text (768 Dimensions, float32).
  • • Storage Engine: PostgreSQL 16.4 CNPG Cluster (3 HA instances on iSCSI).
  • • HNSW Parameters: m=16, ef_construction=64, ef_search=64.
  • • Strength: Semantic similarity, synonym matching, conceptual alignment.

Branch B: Two-Tier Lexical (BM25)

  • • Tier 1 (Primary): In-Memory BM25Okapi (Python singleton, <1.5ms latency).
  • • Tier 2 (Fallback): PostgreSQL tsvector GIN index (English websearch).
  • • Tuning: k1=1.5 (saturation), b=0.75 (length normalization).
  • • Strength: Exact hostnames, serial numbers, error codes, Cisco models.

RRF Fusion & BGE Reranker

  • • RRF Scoring: 1 / (60 + rank_vec) + 1 / (60 + rank_bm25).
  • • Reranker: bge-reranker-base (Remote service, cross-attention scoring).
  • • Confidence Gate: Threshold 0.75 enforces anti-hallucination guard.
  • • Dual LLM: Cloud OpenRouter (15s timeout) ─► Local Llama 3.2 1B fallback.
