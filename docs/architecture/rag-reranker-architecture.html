Cross-Encoder Reranker & Scoring Architecture

Deep Dive: Bi-Encoder (Dense Vector Retrieval) vs Cross-Encoder (BAAI/bge-reranker-base), Title Overlap Boosting, and Remote Deployment

1. Why Rerank? (The 2-Stage Retrieval Pattern)

  • • Scale vs Precision Trade-off: Vector search is fast (ANN) but coarse. Cross-encoders are exact but slow.
  • • Cost Minimization: Running cross-attention on 10,000 documents is impossible (minutes). Running on 20 candidates takes only ~250ms.
  • • False Positives Elimination: Chunks that share superficial keywords but discuss the wrong topic are reliably filtered out.
  • • Token Economy: Sends only the top 5 high-signal chunks to LLM, saving prompt tokens and avoiding context bloat.

2. Title Overlap & Hub Demotion Heuristics

  • • Title Overlap Bonus: Boosts final score by min(0.15 * overlap, 0.45) when query terms explicitly match the document title.
  • • Hub Page Demotion: Pages with titles like "Network", "Server", "IT Support Guide" are penalized by -0.10 to prevent generic index pages from burying specific operational runbooks.
  • • Dynamic Reordering: Specific runbooks with precise CLI commands are elevated over generic introductory overviews.
  • • Fail-Safe Fallback: If reranking fails or times out, the pipeline safely falls back to raw vector similarity order without breaking the chat stream.

3. Production Deployment & Remote Scaling

  • • Model: BAAI/bge-reranker-base (CrossEncoder architecture, max_length=512).
  • • Remote Deployment (Option A): Offloaded to standalone rerank-svc:8080 pod, preserving backend CPU.
  • • Confidence Gate Binding: Sigmoid of top-1 rerank score feeds the 0.75 confidence gate threshold.
  • • Hallucination Defense: If top chunk score remains below 0.75 even after reranking, the LLM is directed to emit a polite caution refusal.
