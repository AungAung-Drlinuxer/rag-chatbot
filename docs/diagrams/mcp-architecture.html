MCP Live-Infrastructure Architecture

Read-only access to the live estate from the assistant · RKE2 cluster drlinuxer-prod, namespace rag-chatbot

Answer path (deterministic first)

  • • Kubernetes / Proxmox / Grafana shapes are matched by code, no model in the loop — faster, cheaper, reproducible
  • • Anything unmatched falls back to a LangGraph ReAct agent that chooses tools itself
  • • The deterministic branch returns the cluster's own output as a markdown table, never re-worded by a model

Read-only, proven not asserted

  • • Rancher: read_only=true, disable_destructive=true, secrets masked
  • • Proxmox: destructive flag deliberately absent
  • • Grafana: --disable-write
  • • Postgres: --access-mode restricted + mcp_reader, execute_sql not exposed

Why two transports

  • • rancher-mcp and grafana-mcp are HTTP-native images
  • • proxmox-mcp is stdio-only, served through our own bridge.js
  • • postgres-mcp and grafana-mcp answer on legacy SSE
  • • Both paths must carry the connector token — the SSE one silently did not, and that single omission produced 401 with a valid token
